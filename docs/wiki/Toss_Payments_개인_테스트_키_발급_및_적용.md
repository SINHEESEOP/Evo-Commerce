# Toss Payments 개인 테스트 키 발급 및 적용

## 배경
Toss Payments 공식 문서에는 별도 가입 없이 누구나 쓸 수 있는 공용 테스트 상점 키(`test_ck_...`/`test_sk_...`)가 공개돼 있다. 연동 자체를 확인하는 데는 충분하지만 다음 두 가지 한계가 있다.

- 문서를 보는 모든 사람이 같은 키를 공유하므로 언제 요청이 몰려 제한되거나 예상과 다르게 동작할 수 있다.
- 결제 내역 조회, 웹훅 URL 등록 같은 계정별 설정은 개발자센터 대시보드 기능인데, 공용 키에는 연결된 대시보드 계정이 없어 이 기능들을 쓸 수 없다.

개인 테스트 계정을 만들면 위 문제 없이 같은 샌드박스 환경(실제 결제는 발생하지 않음)에서 본인 전용 키로 개발할 수 있다.

## 1. 개발자센터 가입
1. [Toss Payments 개발자센터](https://developers.tosspayments.com)에 접속한다.
2. 이메일로 가입한다. 사업자 등록 정보 없이도 테스트(샌드박스) 이용이 가능하다.
3. 가입 완료 시 "테스트 상점"이 자동으로 하나 생성된다.

## 2. 테스트 키 확인
1. 개발자센터에 로그인한다.
2. `내 개발정보` (또는 `API 키`) 메뉴로 이동한다.
3. 테스트 클라이언트 키(`test_ck_`로 시작)와 테스트 시크릿 키(`test_sk_`로 시작)를 각각 확인한다.

두 값 모두 샌드박스 전용이라 실제 카드 결제가 일어나지 않는다.

## 3. 프로젝트에 적용

| 파일 | 바꿀 값 | 비고 |
|---|---|---|
| `.env` | `TOSS_SECRET_KEY` | 로컬 전용 파일, `.gitignore`에 등록돼 있어 git에 올라가지 않는다 |
| `src/main/resources/static/checkout.html` | `clientKey` 변수 값 | 클라이언트 키는 브라우저에 그대로 노출되는 공개 값이라 소스에 직접 넣어도 안전하다 |

> [!CAUTION]
> `.env.example`은 git에 커밋되는 템플릿 파일이다. 여기에는 개인 시크릿 키를 넣지 말고, 지금 들어있는 Toss 공식 문서의 공용 테스트 키를 그대로 둔다. 개인 키는 오직 `.env`에만 넣는다.

## 4. 적용 확인
1. 애플리케이션을 재시작한다. `.env` 값은 부팅 시점에 한 번 읽힌다.
2. `/checkout.html?orderId={주문ID}`에서 결제를 진행한다.
3. 개발자센터 대시보드의 결제 내역에서 방금 진행한 결제 건이 조회되면 개인 키로 정상 전환된 것이다. (공용 키로 결제했을 때는 본인 계정 대시보드에 아무 내역도 남지 않는다.)

## 참고
웹훅 URL 등록은 대시보드에서 계정별로 관리하는 설정이라, 웹훅 수신 흐름을 검증하려면 이 개인 테스트 계정이 반드시 있어야 한다.
